## 2. Flow Notes (invariants carried by each flow)

- **FL-01** is specified authoritatively by `PAYMENT_FLOW.md`: settlement IDs are reserved on the invoice *before* report generation (including pending/rejected purchases); only a finalized `VALID`/`VERIFIED` verdict sets `paid` and issues the access token; `INVALID`/`REJECTED` → `verification_rejected` with a `buyer_refund` operation for the full raw USDC bound to the authoritative payer; `refunded` becomes terminal only after the Circle BurnIntent receipt is `COMPLETE`. RPC/finalization/config failures leave `verification_pending` and never fabricate payout or refund.
- **FL-02** excludes funds already reserved by the automatic payout plan of a paid invoice (no double payment); missing/unavailable claim storage fails closed (`PAYMENT_FLOW.md`).
- **FL-03** rails (`min_sweep_threshold`, `max_sweep_per_epoch`, `max_jit_redeem_per_epoch`, `min_operating_reserve`) and cooldowns are evaluated after the ladder — the ladder proposes, policy disposes. Deterministic by design; see `SECURITY_AUDIT.md` GAP-03.
- **FL-04** tiers only produce *plans*; monetary authority stays with the spend guard and the FL-01 state machine. `decision_source` is recorded on the payload for auditability.
- **FL-05/FL-06** share the session store: incident control actions mutate session state that the lease lifecycle then enforces (a frozen/stopped session stops winning leases).

## 3. Maintenance

1. Any change to invoice status, settlement verification, claim lifecycle, treasury execution, incident or lease behavior updates this document and `SYSTEM_ARCHITECTURE.md` in the same change; `PAYMENT_FLOW.md` remains the source of truth for FL-01.
2. New public routes are registered only in `backend/app/api/v1/endpoints/` routers (factory pattern `create_*_router`); entry points listed here must stay `file:line` accurate — a drift found during refactor is a CRCIP finding, not a doc bug.
3. Public contract changes additionally trigger the API documentation gate in root `AGENTS.md`.
